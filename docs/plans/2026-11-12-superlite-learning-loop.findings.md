- [C4-1] Reflexion stores verbal self-reflections in an episodic text buffer (no weight updates) and reached 91% pass@1 on HumanEval vs 80% for the GPT-4 baseline (2023). Fit: high, a text file of reflections is stdlib-trivial; but evidence is single-task retry loops with test feedback, not cross-run per-repo. (sources: S4-reflexion)
- [C4-2] Voyager's skill library of verified executable code, retrieved by embedding, gave about 3.3x more unique items, 2.3x longer distances and up to 15.3x faster tech-tree milestones vs prior SOTA (Minecraft); gains are for the whole system, not isolated to the library. Embedding retrieval is not stdlib-friendly; keyword/tag lookup is the file-based analogue. (sources: S4-voyager)
- [C4-3] ExpeL (AAAI-24) extracts natural-language insights from success/failure trajectories and recalls past trajectories, showing consistent improvement as experience accumulates; the abstract gives no numbers. Insights are a curated rule list, a good match for a per-repo lessons file. (sources: S4-expel)
- [C4-4] Agent Workflow Memory induces reusable workflows from successful trajectories, giving relative success gains of 24.6% on Mind2Web and 51.1% on WebArena, with fewer steps (arXiv 2024, web navigation not coding). (sources: S4-awm)
- [C4-5] RouteLLM learns routers from preference data and cuts cost by over 2x in certain cases without losing response quality (arXiv 2024, v4 Feb 2025). It needs a quality signal per call; per-repo tier calibration from observed pass/fail by task type is a small-data analogue, not a replication. (sources: S4-routellm)
- [C4-6] FrugalGPT (2023) reports up to 98% cost reduction at GPT-4-level performance via LLM cascades (cheap model first, escalate on low scorer confidence), or +4% accuracy at equal cost; the cascade maps to haiku->sonnet->opus escalation using test/reviewer outcomes as the scorer. (sources: S4-frugalgpt)
- [C4-7] DSPy compiles LM pipelines against a metric: self-bootstrapped pipelines beat standard few-shot prompting by over 25% (GPT-3.5) and 65% (llama2-13b) and expert demonstrations by 5-46% / 16-40% (2023). It needs a measurable metric, a dependency and many LM calls; the idea (metric-gated prompt/skill changes) fits, the library does not. (sources: S4-dspy)
- [C4-8] Evaluating AGENTS.md (ICLR 2026, arXiv Feb 2026): across Claude Code, Codex and Qwen Code on SWE-bench Lite and AGENTbench, LLM-generated context files lowered success by about 0.5-2%, developer-written files gave only about 4% gain, both raised cost (reported over 20%); generic repo overviews did not help, non-standard practices did. Implication: auto-written memory must be minimal, non-redundant with README, and evaluated before adoption. (sources: S4-agentsmd)
- [C4-9] SWE-Exp (arXiv Jul 2025, v2 Feb 2026) distils experience from past issue-resolution trajectories (successes and failures) into an experience bank and reports 73.0% Pass@1 on SWE-bench Verified with Claude 4 Sonnet; the closest coding-agent evidence that cross-issue memory helps, but the gain over its own no-memory baseline was not visible in the abstract and needs checking. (sources: S4-sweexp)
- [C4-10] Agentic Context Engineering (ACE, ICLR 2026) treats context as an evolving playbook updated by incremental delta edits, reporting +10.6% on agent benchmarks and +8.6% on finance tasks; it names two memory-rewrite failure modes: brevity bias (summaries drop domain insight) and context collapse (repeated rewrites erode detail). Fit: itemised append/edit bullet files match; whole-file LLM rewrites do not. (sources: S4-ace)
- [C4-11] An empirical study of agent memory (arXiv May 2025) finds an experience-following property (output closely copies that of the most similar retrieved memory), so errors in stored experiences propagate and some correct-looking runs make misleading memories; it recommends selective addition and deletion and using later task outcomes as free quality labels. Supports gating lessons on evidence and pruning. (sources: S4-memmgmt)
- [C4-12] Claude Code memory docs: CLAUDE.md (human-written, project/user/org scope, AGENTS.md also readable) plus auto memory (Claude-written learnings per repository, shared across worktrees); auto memory loads only the first 200 lines or 25KB each session, and both are context, not enforced config (use hooks to enforce). This sets a size budget and an existing per-repo store a plugin can feed rather than duplicate. (sources: S4-ccmemory)
- [C4-13] Across sources, memory entries are most credible when derived from verified outcomes (tests, reviewer verdicts), kept short, deduplicated and removable; evidence for LLM-authored free-form memory is mixed (ACE and SWE-Exp gains vs AGENTS.md loss), so a per-repo loop should record structured outcomes first and promote lessons only after repeated occurrence. (sources: S4-memmgmt)

# How a run works

The coordinator (Opus, medium effort) never writes project code or runs raw tests. `writing-plans` produces a task graph. With a human orchestrator a plain-language review plan is approved once and the coordinator then writes the agent plan from it; `plan_tools lint --stable` freezes the stable tasks and the tier of each. In a delegated run (the user pre-approved or said "decide yourself") the plan is streamed: stable tasks start building while the fixes are made. Wave 0, the skeleton and stubs, is built first by `implementer-haiku` from a brief the tools write from the plan. Stable tasks are then dispatched by tier: Sonnet `implementer` by default, Haiku for `Kind: mechanical` tasks that are off the critical path (the mechanical lane). Every agent first reads a small prime (the implementer rules, the plan header, the Global constraints, and each stable task's title, Owns, dependencies and Produces/Consumes lines; no plan body, diagrams or spec, so nothing in it goes stale) and then gets its own task text from the current plan with `sl task Tn`, which also prints the Produces lines of what that task consumes, so agents read neighbours themselves instead of asking. `build_prime --prime full` keeps the old whole-plan prime. Consumers build against interface stubs and the `e.g.` contract examples, and integration is one task per package. `commit_task` checkpoints each task's own files (hidden `refs/superlite/*` commits; real commits only with `sl autocommit on`) and starts probes and seam checks. Tests run in the background into `.superlite/test-summary.json`. `package-reviewer` reviews selected tasks or whole packages and fixes its own findings. A review packet (incidents, probe failures, test summary, source excerpts) goes to one fresh `final-reviewer`, which returns findings only, each with a fix tier. Fix-only agents (`fixer-sonnet`, `fixer-sonnet-high`, `fixer-opus`) take them by tier. A fix keeps a decision, so Haiku never fixes. Each round rewrites a file note in `.superlite/fixes/<id>.md`, and a tier that fails twice escalates to a fresh agent primed by the note. `finish` lists the rulings, and `history write` appends the run's rows to `~/.superlite/history.jsonl`.

# Hooks

`hooks/hooks.json` registers these ten. Cursor's `hooks/hooks-cursor.json` registers `session-start` on `sessionStart`, `record-human-reply` and `cost-report` on `beforeSubmitPrompt`, `block-coordinator-edits` on `preToolUse`, the two capture scripts on `subagentStart` and `subagentStop`, and `capture-host-usage` on `stop` and `afterAgentResponse`. Cursor on Windows runs hook commands through PowerShell, where Git for Windows puts only `git` on the PATH, not `bash`; so each Cursor command starts its script through a git alias (`git -c 'alias.sl-hook=!cd "${GIT_PREFIX:-.}" && exec bash ./hooks/<name>' sl-hook`), which runs Git's own bash from the plugin folder. The same command works under `sh` on macOS and Linux. The run hooks are active only while a run marker exists (`.superlite/stable.json`, `prime.md` or `pool.json`, written by the first lint, or `orchestrator.json` or `feature.json` once a superlite session has started). They fail open on bad input.

- `session-start`: injects `using-superlite` at startup, clear and compact. While `.superlite/peers.json` says the run is suspended, it also tells the session not to load superpowers or any plugin with the same lifecycle skills; `sl finish` removes that marker.
- `block-unsafe-kill`: always on for Bash and PowerShell; blocks killing processes by name or pattern (`taskkill /IM`, `pkill`, `killall`, `Stop-Process -Name`). Kill by PID is allowed.
- `block-coordinator-edits`: guards the coordinator (calls without `agent_id`, or in Cursor without `parent_tool_call_id`); subagents always pass. In Cursor a denial is also printed as `{"permission":"deny",...}` with the reason in `user_message`, the field Cursor shows the agent. In every state it denies the model writing `.superlite/orchestrator.json`, `.superlite/feature.json` and `.superlite/human-replies.jsonl`. While a human-orchestrator run is unapproved it denies orchestration: `superlite:*` and `general-purpose` agents and `sl dispatch`, `assign`, `wave0`, `build_prime`, `checkpoint` (old name `commit_task`) and `finish`; file writes pass, so small inline work needs only the human's yes in chat. In feature mode the same denial holds while the prototype's try-out waits for the human (human mode, `.superlite/feature.json` status `tryout`), so the integration build starts only after `sl proto tryout --approve`. During a run it blocks the coordinator from writing project code; it may write `docs/plans/**`, `SPEC*.md`, `docs/**/*.md` and `.superlite/**`, except the prototype worktree `.superlite/sandboxes/**`.
- `rewrite-test-runs`: during a run, rewrites the coordinator's raw test commands into a background `sl run_tests --full`, or `sl run_tests --fast <files>` when the command names test/source paths, and logs a `rule-rewrite` incident. Subagents may not run a bare full suite (exit 2); use `--fast`. It also denies (exit 2, `rule-block`) a known runner inside an `until`/`while` loop or with stdout sent to `/dev/null`; the message points to `sl run_tests --wait`. `until curl ...` and `until [ -f x ]` pass.
- `compact-nudge`: on `UserPromptSubmit`, when a session is due for compact (~35–40 min), adds a host-neutral `additionalContext` nudge. Silent when `SUPERLITE_NO_AUTOCOMPACT=1` or not due.
- `cost-report`: on every `UserPromptSubmit` / Cursor `beforeSubmitPrompt`, and again from `session-start`, injects a one-line `superlite cost: …` summary only after the host has reported usage (`host_usage` in `metrics.jsonl`). Silent before that (no `$0.00` guess). Cursor returns `continue` plus `additional_context` when there is a line. Opt out: `SUPERLITE_NO_COST_REPORT=1`.
- `capture-host-usage`: on Cursor `stop` / `afterAgentResponse` / `subagentStop` (and Claude `Stop` when the payload includes usage), appends a `host_usage` record with the host's own `input_tokens` / `output_tokens` / cache fields, optional `total_cost_usd` / `chargedCents`, and `agent_id` / `agent_type` when present. Writes nothing when token/cost fields are absent. Live cost then shows `agents: …` per named agent when possible.
- `record-human-reply`: on every prompt the human submits while a human-orchestrator run is unapproved, appends one line to `.superlite/human-replies.jsonl` (time, whether it approves, the first 160 characters). A reply approves only when it is short (at most 12 words), has no question mark, and has an approval phrase and no negation, so a message that only mentions approving does not count. It also records while a feature-mode try-out waits (`.superlite/feature.json` status `tryout`, human mode). `sl orchestrator approve` needs an approving reply newer than the review plan, `sl proto tryout --approve` one newer than the prototype's last checkpoint. Only this hook writes the file; it never blocks. In Cursor it answers `{"continue":true}` and finds the project from `CURSOR_PROJECT_DIR` or the first workspace root that holds `.superlite/orchestrator.json`, because Cursor runs plugin hooks outside the project.
- `capture-agent-launch`: during a run, appends a `launch` record (agent id, type, model, description) to `.superlite/metrics.jsonl` after each `Agent` call. On Cursor the same script reads `subagentStart` (`subagent_id`, `subagent_type`, `subagent_model`, `task`).
- `capture-agent-stop`: during a run, appends a `stop` record (agent id, type, transcript path, last message) to `.superlite/metrics.jsonl` when a subagent stops. On Cursor it reads `subagentStop` (`subagent_id`, `summary`, `agent_transcript_path`). Time is the gap between the two records. Live cost reporting prefers `host_usage` over transcript estimates.

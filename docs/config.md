# Config

In `skills/swarm/config/`:

- `models.json`: prices (USD per million tokens) and output speed per model. Edit it when they change.
- `predictor.json`: the time and context coefficients and the size band `predict` uses. Refit with `sl predict --refit`.
- `gitignore.json`: ignore entries per language plus common ones; Wave 0 appends the missing ones to `.gitignore` before any agent runs.
- `testprobe.json`: the hung-test probe's thresholds (see [Tools](tools.md)).
- `routing.json`: task features to tier (`haiku` or `sonnet`), tier agents and limits, and the stats gate. A critical-path task never gets haiku. `batch`: how `dispatch` groups ready tasks of one tier into one agent message: at most `max_tasks` (3), with summed weight at most `capacity` (3), weight by the task's `Complexity N` (up to 3: 1, so three share an agent; 4-5: 1.5, so two; 6 and up: 3, alone; unknown counts as 5), summed `Est. context` within the tier's `max_context_k`. Critical-path tasks run alone, so what they unblock never waits behind a batch. `max_tasks: 1` turns batching off.
- `hosts/<host>.json` (e.g. `hosts/cursor.json`): per-IDE job → model slug candidates. `sl host_models resolve` writes `.superlite/host-models.json` once per run. Plans may set `**Execution:** host=cursor, parallel=multitask, swarm_by=tier` so `dispatch` prints a `SWARM` block; see `skills/using-superlite/references/cursor-tools.md`.

A committed `superlite.json` at the root of the project being built overlays those defaults. A missing file changes nothing. `version` must be `1`. Keys: `cap` (dispatch cap; an explicit `--cap` wins, including 0; otherwise 10), `gitignore` (lines appended after the shipped list and the plan's `**Ignore:**`; shipped lines are never removed), `hosts` (host name → job name → `candidates`, replacing that job's list), `testprobe` (threshold overrides; an explicit path or `SUPERLITE_TESTPROBE_CONFIG` wins), `models` (numeric price fields on existing model names, tagged `source=project`). Unknown keys, including `skills`, exit 2 and name the file. The file does not name skills and has no `check` field. It does not replace `routing.json`. A critical-path task still never uses haiku.

`sl plan_tools stubs` still writes Python stubs that `raise NotImplementedError` when the language is Python. Any other language prints one `stub:` line per Produces signature and a `contract:` line, and writes no `.py` file. `sl plan_tools adapter` still writes `.superlite/probes/adapter.py` and checks it with `compile` for Python. Another language gets `.superlite/probes/seam.ts`, `seam.js`, `seam.go`, `seam.rs`, `seam.cs`, `seam.java`, `seam.rb`, or `seam.txt`, and the first line is `// superlite seam: <language>`. `probe_run` exits 2 for a missing `adapter.py` only when the language is Python or `.superlite/test-cmd.json` is absent.
